API Guide

The v1 API intentionally provides only token authentication, create, update and Markdown download operations. [root] is a literal documentation placeholder for the site's root URL, including scheme, host and optional port. Replace it, credentials and slugs before running an example.

Get and revoke a token

curl -X POST [root]/api/v1/auth/token/ \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"your-password"}'

Authenticated requests use Authorization: Token YOUR_TOKEN. Revoke the active token with:

curl -X POST [root]/api/v1/auth/revoke/ \
  -H "Authorization: Token YOUR_TOKEN"

Create content

Post, Note and Project are deliberately separate resources. The first non-empty Markdown line must be one H1. The server derives title and slug from that heading.

ResourceCreateUpdateDownload
PostPOST /api/v1/posts/PUT|PATCH /api/v1/posts/<slug>/GET /api/v1/posts/<slug>/download/
NotePOST /api/v1/notes/PUT|PATCH /api/v1/notes/<slug>/GET /api/v1/notes/<slug>/download/
ProjectPOST /api/v1/projects/PUT|PATCH /api/v1/projects/<slug>/GET /api/v1/projects/<slug>/download/
 
curl -X POST [root]/api/v1/posts/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"markdown":"# First post\n\nHello world.","visibility":"public"}'

A successful create returns:

{
  "title": "First post",
  "slug": "first-post",
  "visibility": "public",
  "created_at": "2026-07-19T12:00:00Z",
  "updated_at": "2026-07-19T12:00:00Z"
}

You can upload a UTF-8 Markdown file instead of sending a JSON Markdown string:

curl -X POST [root]/api/v1/notes/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -F "file=@my-note.md" -F "visibility=private"

Update owned content

curl -X PATCH [root]/api/v1/posts/first-post/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"markdown":"# Renamed post\n\nUpdated body.","visibility":"private"}'

An H1 change also changes the slug. Slug collisions receive -2, -3 and so on. Only the owner can update content.

Download Markdown

curl -OJ [root]/api/v1/projects/my-project/download/

Public Markdown can be downloaded anonymously. Private Markdown requires the owner or a staff/admin token. List, JSON detail, API delete and API revision endpoints do not exist.

Validation and responses

Files must be UTF-8 .md files no larger than 2 MB. Send either markdown or file, never both. Visibility is public or private. Successful creates return 201; updates and downloads return 200. Invalid input returns 400, missing authentication 401, disallowed ownership 403, and unavailable content 404.

Representative error bodies:

{"content":["The first non-empty line must be a Markdown H1 such as '# Title'."]}
{"detail":"Authentication credentials were not provided."}
{"detail":"Only the owner can update this content."}
{"detail":"No Post matches the given query."}

Integrity scope

Every create and update appends an encrypted snapshot to a SHA-256 hash chain with its actor and timestamp. This detects application-level history changes; it is not a blockchain, independent notary or trusted external timestamp.

v1 API bilinçli olarak yalnızca token ile kimlik doğrulama, içerik oluşturma, güncelleme ve Markdown indirme işlemlerini sunar. [root], dokümanda sitenin protokol, host ve varsa port bilgisini içeren kök adresi yerine kullanılan düz metin placeholder'dır. Örneği çalıştırmadan önce bu ifadeyi, kullanıcı bilgilerini ve slug değerlerini kendi bilgilerinle değiştir.

Token alma ve iptal etme

curl -X POST [root]/api/v1/auth/token/ \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"your-password"}'

Kimliği doğrulanmış isteklerde Authorization: Token YOUR_TOKEN başlığı kullanılır. Aktif token'ı şu istekle iptal edebilirsin:

curl -X POST [root]/api/v1/auth/revoke/ \
  -H "Authorization: Token YOUR_TOKEN"

İçerik oluşturma

Post, Note ve Project bilinçli olarak ayrı kaynaklardır. Markdown içeriğinin ilk dolu satırı tek bir H1 olmalıdır. Sunucu başlığı ve slug değerini bu H1 satırından üretir.

KaynakOluşturmaGüncellemeİndirme
PostPOST /api/v1/posts/PUT|PATCH /api/v1/posts/<slug>/GET /api/v1/posts/<slug>/download/
NotePOST /api/v1/notes/PUT|PATCH /api/v1/notes/<slug>/GET /api/v1/notes/<slug>/download/
ProjectPOST /api/v1/projects/PUT|PATCH /api/v1/projects/<slug>/GET /api/v1/projects/<slug>/download/
 
curl -X POST [root]/api/v1/posts/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"markdown":"# İlk yazı\n\nMerhaba dünya.","visibility":"public"}'

Başarılı bir oluşturma isteği şu yapıda cevap döndürür:

{
  "title": "İlk yazı",
  "slug": "ilk-yazi",
  "visibility": "public",
  "created_at": "2026-07-19T12:00:00Z",
  "updated_at": "2026-07-19T12:00:00Z"
}

JSON içinde Markdown göndermek yerine UTF-8 bir Markdown dosyası da yükleyebilirsin:

curl -X POST [root]/api/v1/notes/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -F "file=@notum.md" -F "visibility=private"

Kendi içeriğini güncelleme

curl -X PATCH [root]/api/v1/posts/ilk-yazi/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"markdown":"# Yeniden adlandırılan yazı\n\nGüncel içerik.","visibility":"private"}'

H1 değişirse slug da değişir. Slug çakışmalarında -2, -3 gibi ekler kullanılır. Bir içeriği yalnızca sahibi güncelleyebilir.

Markdown indirme

curl -OJ [root]/api/v1/projects/projem/download/

Herkese açık Markdown içerikleri anonim olarak indirilebilir. Özel içerik için içeriğin sahibi veya staff/admin token'ı gerekir. API'de listeleme, JSON detay, silme ve revision uçları bulunmaz.

Doğrulama ve cevaplar

Dosyalar UTF-8 kodlu, .md uzantılı ve en fazla 2 MB olmalıdır. Aynı istekte yalnızca markdown veya file gönder; ikisini birlikte gönderme. Görünürlük değeri public ya da private olmalıdır. Başarılı oluşturma 201, güncelleme ve indirme 200 döndürür. Geçersiz veri 400, eksik kimlik doğrulama 401, yetkisiz sahiplik işlemi 403 ve bulunamayan içerik 404 döndürür.

API'nin döndürebileceği örnek hata gövdeleri:

{"content":["The first non-empty line must be a Markdown H1 such as '# Title'."]}
{"detail":"Authentication credentials were not provided."}
{"detail":"Only the owner can update this content."}
{"detail":"No Post matches the given query."}

Hata metinleri şu anda backend tarafından İngilizce döndürülür; HTTP durum kodları ve alan adları her iki dilde de aynıdır.

Bütünlük mekanizmasının kapsamı

Her oluşturma ve güncelleme işlemi; işlemi yapan kullanıcı ve zaman bilgisiyle birlikte şifrelenmiş bir snapshot'ı SHA-256 hash zincirine ekler. Bu mekanizma uygulama seviyesindeki geçmiş değişikliklerini tespit etmeye yardımcı olur; blokzincir, bağımsız noter veya güvenilir harici zaman damgası değildir.
